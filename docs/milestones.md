# SoundDive 개발 마일스톤

Nov 26, 2026 · @silverbug

12월 5일 OT 전에 1·2단계를 모두 끝내고, 개발이 끝나는 12월 4일에 바로 도메인을 구입해 연결합니다. 기획 내용은 [SoundDive 웹사이트 기획서](https://claude.ai/artifact/DTrUbZwsp3KWJcnWLTCQay)를 따릅니다.

구현 방법과 작업별 완료 조건은 [SoundDive 개발 명세](https://claude.ai/artifact/82XPesoNqcPKmrBwBajcqU)를 따릅니다. 개발은 내가 Claude Code로 혼자 하고, 밀리면 공동 개발로 바꿉니다.

## 전제와 위험

남은 기간은 11월 27일(금)부터 12월 4일(금)까지 **8일**이고, 그중 평일 6일은 퇴근 후 시간만 쓸 수 있습니다. 혼자 바이브 코딩으로 만들기에는 빠듯하므로, 하루에 한 덩어리씩 순서대로 만들고 가장 큰 두 덩어리인 공개 페이지와 관리자 화면을 주말 이틀(11/28 토, 11/29 일)에 하루씩 둡니다. 11/29 밤에 회차 저장이 안 되거나 어느 날이든 하루 이상 밀리면 공동 개발로 바꿉니다(아래 '역할 분담').

12월 5일에 실제로 필요한 것은 생각보다 적습니다. 첫 회차 기록은 첫 활동 뒤에야 생기고, 모집 페이지와 결산 페이지는 2월에야 필요합니다. 그래서 12월 4일의 최소 목표는 **첫 활동 기록을 받을 수 있는 상태**로 두고, 모집·결산은 같은 기간에 만들되 밀리면 가장 먼저 뒤로 보냅니다(맨 아래 '밀릴 때 미루는 순서').

## 역할 분담

**개발은 내가 혼자, Claude Code로 합니다.** 혼자 하면 같은 파일을 두 사람이 각자 AI로 고치다 생기는 충돌과 합치는 시간이 없고, 스키마와 결정이 한 사람에게 모입니다. 대신 주말에 두 덩어리를 동시에 만들 수 없어 하루 한 덩어리씩 순서대로 가야 하므로, 밀리면 바로 공동 개발로 바꿉니다.

공동 운영자는 코드 대신 사람이 해야 하는 일을 맡습니다. 개발 환경이 필요 없어 언제든 맡길 수 있습니다.

- 소개·FAQ·모집 문구 작성
- 정리본 AI 프롬프트를 모의 녹음으로 시험하기
- 샘플 회차를 처음부터 게시까지 입력해 보기, 휴대폰 실기기 확인

### 공동 개발로 바꾸는 기준

아래 중 하나라도 해당하면 바꿉니다.

1. 11/29(일) 밤까지 관리자 회차 편집기에서 회차 저장이 되지 않는다.
2. 어느 날이든 그날 몫을 다음 날 저녁까지 끝내지 못했다.

바꿀 때 넘기는 일은 공개 사이트(`apps/site`)입니다. DB를 읽기만 하고 비밀값을 쓰지 않으며 로컬 샘플 데이터로 개발할 수 있어, 넘겨도 위험이 가장 적습니다. 공개 페이지가 이미 끝났다면 남은 함께하기·결산 페이지를 넘깁니다.

전환 비용을 줄이려고 처음부터 세 가지를 해 둡니다. 공동 운영자를 저장소에 미리 초대하고, 규칙 파일(CLAUDE.md)과 문서(`docs/`)를 저장소에 두고, 로컬 실행을 명령 네 개(`pnpm install` → `pnpm db:migrate:local` → `pnpm db:seed:local` → `pnpm dev:site`)로 끝나게 만듭니다. 전환하면 공동 운영자도 저장소를 복제해 Claude Code로 작업합니다. 같은 CLAUDE.md와 권한 설정을 읽으므로 규칙이 저절로 맞춰집니다.

공동 개발 중에는 세 가지 규칙을 지킵니다.

1. 스키마(마이그레이션)는 나만 바꾼다. 공개 사이트에 필요한 컬럼이 생기면 요청한다.
2. 각자 브랜치에서 작업하고 PR로 main에 합친다. 이때부터 main은 PR 필수로 바꾼다.
3. 두 사람의 AI 도구가 같은 규칙 파일(CLAUDE.md)과 같은 문서를 읽게 한다.

### 나만 해야 하는 일

계정 소유자가 해야 하고, 인수인계 때도 한 사람에게 모여 있어야 하는 일입니다.

- Cloudflare 계정과 D1·R2·Access 설정, 허용 이메일 등록
- 유튜브·카카오 API 키 발급과 시크릿 등록
- GitHub 저장소 소유, 공동 운영자 초대, main 브랜치 보호
- 스키마 변경 결정과 보안 점검 판단
- 도메인 결제와 연결

## 사람이 할 일과 바이브 코딩으로 할 일

코드로 표현되는 일은 대부분 AI가 쓸 수 있습니다. 반면 계정·결제·비밀값·판단·실제 사람과의 일은 사람이 해야 합니다.

| 구분 | 작업 |
| --- | --- |
| 바이브 코딩 | Astro 프로젝트 구성, 마이그레이션 SQL, 공개 페이지와 관리자 화면 UI, 정리본 파서와 테스트, 카카오·유튜브 API 연동 코드, 브라우저 사진 처리, 결산 뷰·트리거, 배포 설정 파일, OG 태그 |
| AI가 쓰고 사람이 꼭 확인 | 관리자 인증 검증 코드, 비밀값을 쓰는 코드, 스키마 변경, 무료 한도(요청당 쿼리 50개 등) 대응 로직 |
| 사람이 직접 | 계정 생성·로그인·결제, API 키 발급과 시크릿 입력, Access 허용 이메일 설정, 저장소 권한·브랜치 보호, 도메인 구입, 소개·모집 문구, 디자인 판단, 실제 녹음으로 프롬프트 검증, 보안 점검 결과 판단, 휴대폰 실기기 확인, OT 고지와 닉네임 수집, 사진 모자이크 |

API 키와 토큰 값은 AI 채팅이나 코드에 붙여넣지 말고, 시크릿 입력 명령어로 사람이 직접 넣습니다. 공개 저장소라 한 번 새면 되돌리기 어렵습니다.

## 밀릴 때 미루는 순서

아래 순서로 뒤로 보냅니다. 앞의 것일수록 실제로 필요해지는 시점이 늦습니다.

1. **결산 페이지:** 1기 마지막 회차(2월 말) 전에만 있으면 됩니다.
2. **모집 페이지:** 2기 공고 전에만 있으면 됩니다.
3. **유튜브 후보 선택기:** 없으면 첫 검색 결과를 그대로 쓰고 나중에 고칩니다.
4. **카카오 장소 검색:** 없으면 장소 이름·링크를 직접 입력합니다.
5. **도메인:** 개발이 늦어지면 함께 미루고, OT에서는 workers.dev 주소로 소개합니다.

첫 활동 전까지 반드시 있어야 하는 것은 **회차 입력·게시**와 **회차를 보여 주는 공개 페이지**뿐입니다. 그것도 늦어지면 녹음과 사진만 남겨 두었다가 소급 입력하면 됩니다.
